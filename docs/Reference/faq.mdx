<AccordionGroup>
  <Accordion title="Is Vektra free?">
    Yes. The core submission flow, staff cards, threads, and status updates are free. Starter unlocks branding and customization. Pro unlocks deeper A&R tools, analytics, storage options, support tickets, and more. See [Plans](/free-vs-pro).
  </Accordion>

  <Accordion title="How do I get premium?">
    Run `/premium` in your server to see how to contact the bot owner. After payment you'll get a coupon code for Starter, Pro, or Pro+; redeem it with `/redeem code:<your-coupon>` in your server. Check status with `/pro_status`.
  </Accordion>

  <Accordion title="Can Vektra have a custom avatar or online status per server?">
    Not on Free, Starter, or Pro shared-bot plans. Discord does not let one shared bot use a different avatar or online status per server. Starter and Pro branding applies to messages, embeds, panels, and the bot's server nickname where permissions allow it.

    Pro+ adds hosted white-label bot identity. A Pro+ server can connect its own Discord bot application from the dashboard, including a custom hosted status.
  </Accordion>

  <Accordion title="How does Pro+ white-label bot hosting work?">
    Pro+ servers get a **Pro+ Bot** page in the dashboard. Admins paste their custom Discord bot client ID and token, choose status text, enable hosting, and invite the custom bot. Vektra stores the token encrypted and the VPS manager starts a dedicated worker for that server.
  </Accordion>

  <Accordion title="Can the Pro+ custom bot be invited to the wrong server?">
    Discord's invite screen may show any server where the user can add bots. The hosted worker is still locked to the configured Pro+ server. If the custom bot joins another server, it leaves automatically.
  </Accordion>

  <Accordion title="What happens when Pro+ expires?">
    The white-label bot worker stops automatically when Pro+ expires or is removed. Saved configuration remains stored so it can be reused after renewal, but the custom bot will not stay online without active Pro+.
  </Accordion>

  <Accordion title="How many Pro+ custom bots can Vektra host right now?">
    Pro+ white-label hosting is currently a controlled beta with a default limit of **5 active custom bots** on the VPS.
  </Accordion>

  <Accordion title="Why does the submission form only have five fields?">
    Discord modals only allow up to five text inputs. Vektra uses these for the core demo fields. Starter, Pro, and Pro+ servers can customize the optional message prompt with `/form`.
  </Accordion>

  <Accordion title="What happens to artist attachments?">
    Attachments sent in artist DM replies are reuploaded into the staff thread when they fit Discord's upload limit. If a file is too large or cannot be downloaded, Vektra includes the original temporary Discord attachment link as a fallback.
  </Accordion>

  <Accordion title="An artist's DM reply didn't reach our staff thread. Why?">
    DM reply forwarding requires an active paid tier and only works when the artist **replies directly** to a message the bot sent them. A brand-new DM to the bot won't be forwarded. Always start contact using the **DM** button on a submission card.
  </Accordion>

  <Accordion title="Where is our data stored?">
    Free and Starter servers use managed storage. Pro and Pro+ servers can pick a storage region with `/storage region:<region>` (West US, Europe UK, South-East Asia), or connect their own Neon database with `/setup_db`.
  </Accordion>

  <Accordion title="What happens to our data when we change storage?">
    Vektra migrates existing submissions, tickets, branding, and Pro settings before switching. This also applies when moving from one custom Neon database to another. Old managed storage is cleaned up after a successful move.
  </Accordion>

  <Accordion title="Why do I only see some servers in the dashboard?">
    The dashboard uses your Discord login. It only shows servers where you have Admin or Manage Server permission and where Vektra is installed. Pro-only dashboard tools require that server to have an active Pro or Pro+ tier.
  </Accordion>

  <Accordion title="Can I review submissions from the website?">
    Yes, on Pro and Pro+. You can approve, reject, update status, DM artists, export CSV files, and view analytics from the dashboard. Approval and rejection actions also DM the artist.
  </Accordion>

  <Accordion title="Who can submit release requests?">
    Server admins can submit release requests with `/make-release`, and admins can check that server's release status with `/check-releases`. Pro and Pro+ servers can also submit release requests from the dashboard Releases page.
  </Accordion>

  <Accordion title="Why do release emails need names beside them?">
    Release requests require email IDs for all artists and the label owner. Vektra needs the form to clearly show which email belongs to which person, for example `Owner - owner@email.com` and `Artist Name - artist@email.com`.
  </Accordion>

  <Accordion title="Does the dashboard use AI to check release metadata?">
    No. The dashboard release form asks for each required field separately, so it validates the fields directly. The Discord `/make-release` modal still uses the metadata checker because Discord modals have fewer fields.
  </Accordion>

  <Accordion title="Does Vektra take a distribution fee?">
    On the free tier, release distribution handled through Vektra has a **10% service fee**, so the label keeps **90%**. Paid tiers keep **100%**.
  </Accordion>

  <Accordion title="Can users see each other's submissions?">
    No. Submission cards appear in your private staff channel. Submitters only see their own submissions via `/my_subs`, `/my_demos`, `/my_stats`, and `/submission`.
  </Accordion>

  <Accordion title="How do support tickets stay private?">
    The public panel is just a button. When pressed, the actual ticket card is posted to your staff-only channel. The user only gets a confirmation, and staff reach them via the DM button.
  </Accordion>

  <Accordion title="Why does the leaderboard not match nicknames I remember?">
    The leaderboard groups by Discord user ID, not display name. That way, name changes and nickname variations don't split an artist's stats.
  </Accordion>
</AccordionGroup>
